# VPS redeployment

Optional argument: a label (otherwise `"<short-sha> <summary>"` of the last commit).

**Golden rule: a redeployment = code sync + RESTART. NOT a reset.** The `state_*` (paper) and `live_state_*` (real, NEVER touched) dirs are accumulated data. Wiping/`rm -rf` a state dir = permanent loss — do it ONLY if the user explicitly asks, and after `archive.py`.

Prod lineup: the **zlead race** generated by the watchdog — 4 variants (`zlead`/`zleadmk`/`zleadx`/`zleadn`) × 6 coins (btc/eth/sol/xrp/doge/bnb) × 2 frames (5m/15m) = 48 crypto runners, + 3 events + 3 copy-mirror + the dashboard. No list to maintain: `COINS`/`VARIANTS`/`FRAMES` are at the top of `deploy/watchdog.sh`, the gates in `presets.py`. A variant = a `zlead(...)` in presets / a `Coin(...)` in `coins.py`.

## Steps

1. **Validate locally** — blocking:
   ```bash
   python3 -m py_compile pmlab/*.py main.py webdash.py archive.py run_live.py
   for s in zlead zleadmk zleadn; do
     timeout 60 python3 main.py --strategy $s --interval 15m --underlying btc \
       --state-dir /tmp/smoke_$s --ticks 3 --poll 5 2>&1 | tail -3
   done
   node --check webdash_assets/app/**/*.js && node webdash_assets/app/format.test.mjs
   ```
   Every brain must tick with no `tick error`.

2. **Sync the code**:
   ```bash
   rsync -az --exclude '__pycache__' pmlab webdash_assets main.py webdash.py archive.py \
     <vps-user>@<VPS_IP>:~/pmlab/
   scp deploy/watchdog.sh <vps-user>@<VPS_IP>:~/pmlab/watchdog.sh   # if modified
   ```
   `webdash_assets/` is **mandatory** (dashboard boot guard).
   - **Front-only** (just `webdash_assets/`): app code served `no-store` → rsync + browser reload, **NO restart**.

3. **RESTART (the normal case, no reset)** — upload a script via `scp` and run it over ssh (never an inline heredoc):
   - `pkill -f "[m]ain.py"` (crypto runners; bracket pattern MANDATORY — otherwise the SSH session kills itself) — leave events/copy alone if untouched;
   - `bash watchdog.sh` → relaunches with the new code (dedup by `--state-dir`, states PRESERVED);
   - restart the dashboard if webdash.py changed: `pkill -f "[w]ebdash.py"` then `bash watchdog.sh`.

4. **MODEL change (sizing/fee) — correction IN PLACE, never reset**: pause the watchdog cron, stop the runners, run the exact correction tool that reads the CURRENT journal (`tools/defee_paper.py` for the fee, `tools/recompute_sizing.py` for a resize — ⚠ that one reads `.orig` and would lose recent trades: only use it for a genuine one-time resize), keep the `.prefee`/`.orig` backups, restart, restore the cron.

5. **Reset (ONLY if explicitly requested)**: `python3 archive.py --label "…"` first (purge same-label records from `history/runs.json` if re-archiving), THEN `rm -rf` the targeted state dirs + logs, then `bash watchdog.sh`.

6. **Verify from the outside**:
   ```bash
   curl -s --max-time 10 http://<VPS_IP>:8420/all      # runners present, fresh metrics
   curl -s --max-time 10 http://<VPS_IP>:8420/history  # archives intact
   ```
   Then tail the VPS logs: no `error`, one tick per runner.

7. **Commit + push** to main if not already done.

## Never

- **Reset / `rm` a state dir without an explicit request** (the cause of the data loss already paid for — see memory no-unrequested-destructive-ops). A redeployment preserves states.
- Re-run `recompute_sizing` on a live journal (it reads the frozen `.orig` → loses accumulated trades). In-place correction = `defee_paper`-style.
- Touch `live_state_*` or the armed real pilots.
- pkill/pgrep without the bracket pattern.
